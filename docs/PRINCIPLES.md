# AAClock 技术原理

按模块逐个拆开：每个模块**为什么能工作**、它的数学在哪里、状态归谁、时序约束是什么、代价记在哪一笔。README 讲设计意图与取舍，本文讲实现原理；两者冲突时以代码为准。

对应工作树：`73940b7`（master）。

## 0. 一帧里发生的事

```
  Date.now() ────────▶ time-model ──▶ 三针角度 uAng / 读数 hh:mm:ss.mmm
  拨针·校准·时区 ─────▶  offset / zoneShift / paused / quantize

  CSS 变量 ──────────▶ controller ──▶ GlPalette（9 色，主题切换时才送）

  控件·键盘·指针 ─────▶ main 的字段 ──▶ FrameParams（analytic/samples/field/…）

                                     ▼
                              renderer.draw ──drawArrays(3)──▶ GL 缓冲
                                     │
                       readPixel(1px) ◀┘  readBlock(w×h)
                                     ▼
                              loupe ──▶ 放大画布 + 覆盖层取样框
```

每帧的固定次序（`main.tick`）：取 `Date.now()` → 算角度 → `renderer.draw()` → `drawLoupe()`（含两次 `readPixels`）→ 走时读数 → fps → 节流写 DOM。

有一条硬约束决定了上面这个次序：上下文用 `preserveDrawingBuffer: false`，绘制缓冲在帧末作废，所以读像素必须发生在同一个 rAF 回调里、且在该帧绘制之后。

模块与状态归属：

| 模块 | 文件 | 占有什么状态 |
|---|---|---|
| 时间 | `clock/time-model.ts` | `offset`、`zoneShift`、`paused`、`frozenMs`、`motion` |
| 几何常量 | `clock/DIAL.ts` | 一份常量（供命中测试） |
| 渲染 | `clock/dial.frag`、`clock/fullscreen.vert`、`clock/renderer.ts` | GL 上下文、程序、uniform 位置、调色板 |
| 取样 | `clock/loupe.ts` | `spanPx`、反查表、放大画布、覆盖层 |
| 配色 | `themes/controller.ts` | 当前主题 id、是否跟随系统 |
| 装配 | `main.ts` | 视图开关、尺寸、指针与拖动状态 |
| 颜色运算 | `color.ts` | 无状态 |
| 构建 | `vite.config.ts` | 四个产物变体与六个插件 |

## 1. 时间模型（`time-model.ts`）

### 1.1 四个量的代数

```
absolute(now) = paused ? frozenMs : now + offset
wall(now)     = absolute(now) + zoneShift
```

指针与读数都消费 `wall`。`offset` 只被两件事改（拖动累加、校准清零），`zoneShift` 只被时区选择器改。两个所有权分开，意味着校时不会毁掉时区、换时区不会动校准值。

`zoneShift` 的语义是"显示偏移"，不是"换算到某地时间"：`setAbsolute` 会先把它减掉再写进 `offset` 或 `frozenMs`，所以 `offset` 与 `frozenMs` 始终是 UTC 基准量。

### 1.2 暂停与恢复是赋值而非累加

`pause()` 存 `frozenMs = quantize(nowMs() + offset)`，不含 `zoneShift`。`resume()` 做的是：

```
offset = frozenMs - nowMs()
```

看起来像"追平"，其实不是：这条式子的作用只有一个，让 `absolute(now)` 立刻等于 `frozenMs`。同时它是**赋值**而不是 `offset += …`，因为 `frozenMs` 里已经含了暂停期间被拖动改过的量（`setAbsolute` 在暂停态直接推 `frozenMs`），累加会把那部分算重。恢复后显示值与冻结值连续，指针不跳；要追平真实时间只有按校准（`reset()` 把 `offset` 清零、暂停中则把 `frozenMs` 挪到"现在"）。

### 1.3 量化与时间轴上的别名

`quantize` 在跳秒模式下 `floor(absMs / 1000) * 1000`。注意它作用在 `absolute`（UTC 基准）上，而 `zoneShift` 恒为整小时，两者对秒边界完全一致，所以"UTC 基准取整"与"墙上时刻取整"等价。这是一条成立但脆的不变量：时区若扩到半小时区就会破。

别名是同一个操作在两个轴上的两种表现：空间上是"1 点/像素"，用一格采样读一条细边；时间上是 1 Hz 采样读一支连续旋转的秒针。`setTick` 在暂停态会用新规则重算 `frozenMs`，所以切到跳秒时冻结的读数会立刻对齐到整秒，不会停在半秒上。

### 1.4 角度映射

```
a = (t mod T) / T · TAU      T = 12h（时） / 1h（分） / 1min（秒）
```

先 `wrapDay` 再取模，两步都写了负值保护（JS 的 `%` 会返回负数）。时针的 `t` 是"当天已过毫秒数"，没有截断到整点，所以连续模式下时针是平滑爬行的，不是一格一格跳。

`pointerAngle(cx, cy, x, y) = atan2(x - cx, cy - y)`：分母是 `cy - y`（不是 `y - cy`），这样得到的是"0 指向 12 点、顺时针为正"，与着色器里 `vec2(sin a, cos a)` 的方向约定严格一致。拨针的增量和渲染的角度说的是同一个数。

### 1.5 边界：纯计算

这个模块不读时钟、不碰 DOM：`now` 由调用方注入（主循环里是 `nowMs()`）。所以时间模型可以离线对拍，暂停/恢复/量化的行为不需要浏览器就能验证。

## 2. 几何常量与两把尺子（`DIAL.ts`）

### 2.1 两个像素尺度

```
p_canvas = (gl_FragCoord.xy - 0.5·uRes) / (0.5·min(uRes))
```

`gl_FragCoord` 是像素中心（半整数），相邻像素相差 1，所以一个设备像素在 `p_canvas` 上的长度就是：

```
uPx = 2 / min(uRes.x, uRes.y)
```

盘面被整体缩进了一圈，`p_dial = p_canvas / FIT`，于是：

```
uPxDial = uPx / FIT
```

`uPxDial > uPx` 看起来反直觉，其实是同一句话的两种说法：盘面空间的单位比画布空间的单位小，同一段物理距离在盘面单位下数值更大。于是"一个像素在盘面空间里有多长"是 `uPxDial`，把盘面空间的长度除以它就得到它跨几个像素。

拿 720 px 画布算：`uPxDial = 2 / (720 × 0.84) = 0.0033069`。

### 2.2 FIT = 0.84 的定量约束

投影圆心 `(0, -0.045)`、半径 `R_FACE = 0.862`，最大外延 `0.907`（盘面单位）。画布边缘对应盘面半径 `1 / 0.84 = 1.1905`，两者相距 `0.2835`。

投影的强度是 `exp(-14 · d) · uShadowAlpha`，在画布边缘处剩 `exp(-14 × 0.2835) = exp(-3.97) ≈ 1.9%`。浅色主题 `--shadow` 的 alpha 是 0.04 到 0.11，残量不到 0.2%；暗色主题 alpha 0.3 上下，残量 0.6%。都在一个色阶以内，看不出边界。

反过来推：若 `FIT = 1`，边缘处剩 `exp(-14 × 0.093) = 27%`，暗色主题下就是 8% 的强度在画布边界上被硬切一刀，肉眼可见一条方形直边。**FIT 是"让投影在到达画布边界前衰减到 2% 以下"的那个尺度**；它顺带把盘面直径压到画布短边的 72.4%（`0.862 × 0.84 × 2 / 2`），四周那圈余地正好给顶栏当浮层的落脚点。

### 2.3 常量之间的比例

| 量 | 值 | 在 720 px 上的实像素 |
|---|---|---|
| `uPxDial` | 0.0033069 | 1 px |
| 分针位刻度 角宽 `wTickMinute` | 0.0026 rad | 半宽 0.62 px / 全宽 1.24 px |
| 分针位刻度 径向 | 0.786 − 0.742 | 全厚 13.3 px |
| 整点刻度 角宽 | 0.0052 rad | 全宽 2.47 px |
| 整点刻度 径向 | 0.786 − 0.700 | 全厚 26.0 px |
| 秒针锥 起端半径 | 0.0085 | 直径 5.1 px |
| 秒针锥 尖端半径 | 0.0048 | 直径 2.9 px |
| 秒针尾程 `tSec` | 0.148 | 44.8 px |
| 秒针全长 `lSec` | 0.706 | 213.5 px |
| 轴心三层的半径 | 0.052 / 0.037 / 0.0125 | 31.5 / 22.4 / 7.6 px |

两档刻度的角宽是 1:2、长度是 1:1.95，接近等比，所以视觉上"长短粗细一起变"而不是只变长。三针长度 0.404 / 0.618 / 0.706，两两差值约 0.09 到 0.21。

分针位刻度全宽只有 1.24 px，落在 1 到 2 个像素之间。这就是它最先露出阶梯的原因：整条刻度要么被一个像素完整盖住、要么被两个像素各盖一半，覆盖率永远处在斜坡上，采样稍有相位差就变一个色阶。

### 2.4 常量在两处存在

`dial.frag` 里有一份 `const` 常量，`DIAL.ts` 里有一份等值副本。GLSL 那份是渲染的真值，`DIAL.ts` 只给命中测试用（`lHour` / `lMin` / `lSec` / `tSec` / `fit`）。改几何必须同时改两处，这里没有编译期保障。记为待收敛项（§11.1 第 6 条）。

## 3. SDF 图元（`dial.frag` 上半）

### 3.1 `sdCircle` / `sdBox`

`sdCircle = length(p) - r`，精确欧氏距离。`sdBox` 的两项各管一半：`length(max(d, 0))` 是点在盒外时到角的距离，`min(max(d.x, d.y), 0)` 是点在盒内时到最近边的负距离，相加在两种情形下都给出精确的有符号距离。带是 `abs(sd) - w`：把"到曲线的距离"变成"到曲线 ±w 之外的距离"，得到宽度 `2w` 的环（收边环、轴心环、秒针尾环都用它）。

### 3.2 `sdRoundCone`

两端半径不同的锥形胶囊（两端各一个球体加公切面），三个分支分别对应点落在 `a` 端球、`b` 端球、侧面：

```
ba = b - a,  l2 = |ba|²,  rr = r1 - r2
a2 = max(l2 - rr², 0)                    // 公切线段长度的平方
y = (p - a)·ba,   z = y - l2
x = (p - a)·l2 - ba·y                    // 垂直于 ba 的分量，含 l2 倍缩放
k = sign(rr)·rr²·|x|²
sign(z)·a2·|z·√l2|² > k  →  b 端：√(|x|² + z²·l2)/l2 - r2
sign(y)·a2·|y·√l2|² < k  →  a 端：√(|x|² + y²·l2)/l2 - r1
否则                      →  侧面：(√(|x|²·a2/l2) + y·rr)/l2 - r1
```

代 `rr = 0` 验证退化：此时 `a2 = l2`、`k = 0`，侧面式变成 `√|x|²/l2 - r1`，而 `x / l2` 正是 `p - a` 垂直于 `ba` 的分量，即"点到轴线的垂距"，于是它退化为标准圆柱距离；`a` 端式变成 `√(|x|² + y²l2)/l2 - r1 = |p - a| - r1`。`r1 == r2` 时三个分支同时给出正确结果，不需要特判。

两处退化保护：

- `l2 < 1e-12`（`a` 与 `b` 重合）直接返回球距离。本文件的调用点都不会重合，这行是给"日后改几何常量"兜底的，因为原式里的 `1/l2` 会直接炸成 `Inf`/`NaN`。
- `a2 = max(l2 - rr², 0)`。当 `|r1 - r2| > |b - a|` 时公切线不存在（退化锥），原式里 `a2 < 0`，`sqrt` 出 `NaN`。

### 3.3 `sdTick`：极坐标 + 弧长近似

一支刻度是"指向圆心的径向短条"，这个形状在极坐标里是矩形，所以做法是把点转成 `(角差, 半径)` 再当 `sdBox` 算：

1. `len = length(p)`；`len < 1e-5` 时 `atan(y, x)` 是 0/0 未定义。极限可以算：`rad = len - (rOut + rIn)/2 → -(rOut + rIn)/2`，第一项 `thc·len → 0`，于是 `sdBox → (rOut + rIn)/2 - (rOut - rIn)/2 = rIn`，且与角度无关（每支刻度的极限相同），所以直接返回 `rIn` 既避开奇点又让场在圆心连续。
2. `count < 1` 时 `TAU / count` 溢出，几何上无意义，按"没有刻度"返回 `len`。
3. `thc = th - step·floor(th / step + 0.5)`，其中 `step = TAU / count`，结果落在 `[-step/2, step/2)`。写成 `floor(x + 0.5)` 而不是"先取模再折半"，是为了对负的 `th` 同样正确。
4. 角差换弧长：`thc · len`。**这是本文件唯一的近似**：真实的垂直距离是 `len·sin(thc)`，这里用 `θ` 代 `sin θ`。分针位的 `|thc| ≤ 0.0524 rad`，`sinθ/θ` 与 1 的偏差小于 0.05%，远小于半个像素。
5. 在 `(弧长, 半径)` 平面里 `sdBox`，半宽 `(wAng·len, (rOut - rIn)/2)`。切向半宽随 `len` 线性增长，意味着刻度的两条边在笛卡尔空间里是指向圆心的径向线，这正是真表盘上刻度的画法。
6. `atan` 在负半轴有分支割线，但 `2π / step = count` 是整数（60、12 都是），割线正好落在某支刻度的中心角上，模掉以后 `thc` 连续性不被破坏。这也是 `count` 必须整除的原因：不整除时割线会从一支刻度中间穿过去。

### 3.4 组合

并集一律 `min`。轴心几何上是"环 ∪ 盘 ∪ 点"的并集，分三层画只是为了各层颜色不同（环取 `uCard`、盘取 `uInk`、点取 `uAccent`）。秒针是"锥 ∪ 近针尖的细环"。

秒针晕影算的是到**线段**的距离：

```
t = clamp(dot(p, sd), -T_SEC, L_SEC)     // 投影参数钳在针身两端
d = length(p - sd·t)                     // 最近点到线段的距离
```

不钳这一下，`t` 就变成到无限直线的参数，晕影会顺着针的方向铺满整个画布。

## 4. 覆盖与合成

### 4.1 覆盖率即 alpha

画布从 `uBg` 起底（不透明），此后每一层都是 `mix(dst, src, cov)`。着色器里所有颜色 uniform 都是 `vec3`（不透明），所以整幅图里唯一的透明度来源就是覆盖率本身，再加上投影那个独立强度。这条纪律的收益在覆盖场视图里兑现：场光滑、不连续只出现在阈值化那一步。

`color.ts` 里的 `over()` 是通用式（处理 dst 也非不透明的情形），只用在把 `--border` 的 `rgba()` 压到 `--bg` 上，因为 GL 那边只有实色。

### 4.2 解析覆盖的精确性

```
covAA(d) = clamp(0.5 - d / uPxDial, 0, 1)
```

**对与像素轴对齐的直边，这条式子是恒等式而不是近似。** 取单位像素（边长 1，中心为原点）、边垂直于 x 轴、到中心的距离 `t`（向内为正），边以内的面积就是 `0.5 + t`（区间长度），正是覆盖率。

斜边有偏差。设边的单位法线为 `n`，覆盖面积对 `t` 的导数等于边在像素内的弦长 `L(t)`：

```
A(t) = 0.5 + ∫₀ᵗ L(s) ds        A(t) - covAA(t) = ∫₀ᵗ (L(s) - 1) ds
```

`n` 与像素轴对齐时 `L ≡ 1`，偏差恒为 0。`n` 取 45° 时，边切过像素内部的那一段里 `L(s) = √2 - 2s`，于是偏差 `= (√2 - 1)t - t²`，在 `t = (√2 - 1)/2 ≈ 0.207 px` 处取最大值：

```
(√2 - 1)² / 4 ≈ 0.0429
```

也就是 45° 斜边上最大约 4.3% 的覆盖率偏差，其它角度介于 0 与它之间。

这是所有"一次采样 + SDF 线性斜坡"方案的共同性质，不是本实现的缺陷。**这个量级也是把解析覆盖当作参照值的依据**：9×9 的误差包络是 `1/(2n) = 5.6%`，解析覆盖的偏差不比它大，成本却只有它的 1/81。

曲边（圆弧、圆角）上，误差由 `px / R` 控制，半径越大越接近直边。表盘上曲率最大的两处是轴心点（半径 0.0125 盘面单位，720 px 下约 3.8 px）与秒针尾环（约 6 px），它们是把"边当直边"这一假设推得最远的地方。

### 4.3 n×n 子样本的误差包络

子样本位置是每个等分子格的中心：

```
sub = (i + 0.5) / n - 0.5,   i = 0 … n-1
```

对轴对齐直边（距中心 `d`，以内区域），第 `i` 个子样本落入内部的条件是 `(i + 0.5)/n - 0.5 < -d`，即 `i < n(u + 0.5) - 0.5`（`u = -d`）。计数 `k` 满足这个条件，估计值 `k/n`，精确值 `u + 0.5`。由上式可得

```
k / n = u + 0.5 + ε,   |ε| ≤ 1 / (2n)
```

半个子格，这就是误差包络的来源。

以上推导针对与像素轴对齐的边。斜边的弦长随偏移变化，严格推导更繁，但把 45° 边代进同一个计数式，最坏相位（边正好穿过像素中心）给出的误差同样顶到 `1/(2n)`：n = 2 是 0.75 对 0.5，n = 3 是 0.667 对 0.5，n = 4 是 0.625 对 0.5。

把 README 那张表的实测值还原一遍（长刻度的竖直边缘距像素中心 `d = +0.12 px`，即 `u = -0.12`，解析覆盖 0.38，判据是 `t < -0.12`）：

| n | 子样本偏移 | 落入内部 | 覆盖率 `k/n` | 误差 |
|---|---|---|---|---|
| 2 | −0.25, +0.25 | 1 | 0.500 | +0.120 |
| 3 | −0.333, 0, +0.333 | 1 | 0.333 | −0.047 |
| 4 | −0.375, −0.125, +0.125, +0.375 | 2 | 0.500 | +0.120 |
| 5 | −0.4, −0.2, 0, +0.2, +0.4 | 2 | 0.400 | +0.020 |
| 6 | −0.417, −0.25, −0.083, +0.083, +0.25, +0.417 | 2 | 0.333 | −0.047 |

与 README 测得的 0.496 / 0.331 / 0.496 / 0.397 / 0.331 相差 0.004 上下，来自两点：那支刻度不是纯轴向边缘（有径向倾斜），以及读数是着色器输出的 8 位量化值。

n = 4 与 n = 2 读数相同不是巧合，是 `2/4 = 1/2` 这一处数值巧合；n = 6 与 n = 3 相同同理。误差随 n 振荡而不单调下降，因为栅格相位固定，边界擦过哪一格取决于 n 的奇偶与小数部分。**看收敛要看包络按 `1/(2n)` 收缩**（n = 2 到 6 的包络是 0.25 / 0.167 / 0.125 / 0.1 / 0.083），不看单点。这也是上限取 9 的理由：包络更窄，收缩的样子更容易看出来。

n = 1 是同一公式的特例：唯一子样本落在像素中心，覆盖率退化为 0 或 1，即 1 点/像素。

### 4.4 混合空间

sRGB 直混在编码值上插值。黑白边（0 与 1）在覆盖率 0.5 处得到编码值 0.5，也就是 sRGB 128。

线性光路径是 `pow(mix(pow(d, 2.2), pow(s, 2.2), cov), 1/2.2)`：先升到 2.2 次幂近似线性光，插值，再开回来。同样的 0.5 覆盖率得到 `0.5^(1/2.2) = 0.73`，sRGB 187。

两者相差 59 个色阶，这就是"边缘在 sRGB 直混下偏暗"的量化来源：物理上正确的那一个更亮，因为浅色在感知编码下占的码位更多。真实显示器是 sRGB 分段传递函数，这里用 `pow(2.2)` 近似，两者在暗部差异最大、在 0.5 附近只差 0.02 上下，够用来演示，不值得引分段函数。

超采样路径的线性光走的是另一条路：逐样本着色后先转线性再累加平均（`main` 里那两段 `pow`），比"平均后再转"更接近物理，因为平均必须在光量上做。两条路径合起来意味着 `uLinear` 同时管"图层怎么叠"和"样本怎么平均"。

### 4.5 图层顺序

从 `uBg` 起，逐层 `over`。顺序里有两处依赖值得点出：

- 刻度必须先算整点档的覆盖率 `cHour`，再让分针位档乘 `(1 - cHour)`。短档在长档处让位，不是靠绘制顺序压住（那样会在交叉处出现两色混叠），而是靠覆盖率相乘直接挖掉。
- 投影画在盘面之前，只在外侧可见；内侧被盘面盖住，所以不需要任何裁剪。这也是 `FIT` 必须存在的原因（§2.2）：投影的可见部分正好是画布边缘到盘面之间那一圈。

秒针晕影是唯一一个"用光滑 alpha 直接当覆盖率"的层（`exp(-d²·300) · 0.16 · uGlow`），不走 `covOf`：它本来就不是几何边缘，是一支高斯笔刷，跳秒模式下 `uGlow = 0` 直接关掉。

## 5. 覆盖场视图

把关键图元的并集距离 `d` 画出来：

```
px  = d / uPxDial
t   = clamp(px, -6, 6)
col = mix(uAccent, uBg, clamp(0.5 + t / 12, 0, 1))
```

`t = -6`（内部深处）是 `uAccent`，`t = +6` 是 `uBg`，过渡带 12 像素宽。等距线用 `iso = abs(fract(px) - 0.5)`：`px` 为整数时 `fract = 0`、`iso = 0.5`（最亮），`px` 落在半像素处时 `iso = 0`。于是 coral 的宽带正好压在"距离等于整数像素"的位置上，那是一把以像素为刻度的尺子。

这张图证明的事：距离场本身是光滑的（除图元的角点），正常视图里看到的所有锯齿都来自把光滑场按像素阈值化。`uField` 在 `main` 里优先于一切分支，连超采样都不走，所以覆盖场的成本恒为一次 `sdKeyUnion`，与采样档位无关。

就地验证：把采样调到 1 点/像素再切到覆盖场，画面不变（覆盖场不经过采样路径）；切回正常视图，锯齿出现的位置就是 `|d| < 0.5 px` 的那条带。

## 6. 渲染器（`renderer.ts`）

### 6.1 上下文参数逐条

| 参数 | 取值 | 理由 |
|---|---|---|
| `alpha` | `false` | 画布不透明，不再与页面合成。副作用是 `readPixels` 的 alpha 恒为 255（放大镜里 `toHexA` 那条分支实际是防御性的） |
| `antialias` | `false` | 项目自己算覆盖，GL 的 MSAA 会在同一处再平均一次，直接毁掉"1 点/像素"这一档的对照 |
| `depth` `stencil` | `false` | 用不到 |
| `preserveDrawingBuffer` | `false` | 决定读像素必须在本帧之内（§0） |
| `powerPreference` | `high-performance` | 单独一个全屏着色器，希望落在独显上 |

另外 `gl.disable(DITHER)`：抖动的量级就在一个色阶上下，与"放大镜里数色阶"的目的直接冲突；`gl.disable(BLEND)`：合成全部在着色器里；`gl.disable(DEPTH_TEST)`：无深度。

### 6.2 全屏三角形

顶点着色器只用 `gl_VertexID`：

```
v = vec2(float((gl_VertexID << 1) & 2), float(gl_VertexID & 2))   // (0,0) (2,0) (0,2)
gl_Position = vec4(v * 2.0 - 1.0, 0.0, 1.0)                       // (-1,-1) (3,-1) (-1,3)
```

配一个空 VAO，没有顶点缓冲、没有属性传参。相比两个三角形，它没有对角线上的重复着色（对角像素只被覆盖一次），也没有顶点数据。

### 6.3 uniform 装配

每帧写 9 个标量/向量 uniform；9 个颜色只在 `setPalette` 里写一次（主题切换时才发生）。`uPx` 用 JS 算好而不是在着色器里算，省掉每帧一次除法；`uPxDial = uPx / FIT`。

### 6.4 `readPixel` / `readBlock`

- 缓存按 `key = iy·size + ix`；`draw()` 与 `resize()` 都把 `cachedPixel` 置 −1。主循环里"读中心像素"与"读一块"是两次 `readPixels`，一次 1×1、一次 w×h，无法合并，但同一帧内不会重复读同一格。
- `drawArrays` 之后 `gl.flush()`：让命令进队列，后续 `readPixels` 才有数据。
- 代价：`readPixels` 是一次管线停顿，读 1 格与读 16×16 的差别在驱动路径而不在带宽。这就是它只在放大镜开着时每帧发生的原因；关掉放大镜后主循环完全不回读。
- 越界：`readPixel` 返回 `null`（坐标钳制由调用方做），`readBlock` 越界部分保持 0（`Uint8Array` 初值）。

### 6.5 失败路径

三类 `ShaderError`：拿不到上下文、编译失败、链接失败。`annotate()` 把 infoLog 里的 `0:N` 行号映射回源码行贴进 `#fatal`，省掉在黑箱里猜。`main` 在 `boot` 里捕获构造期与 `start()` 期两处；`webglcontextlost` 里 `preventDefault()` 后给一条可读原因，不白屏。

## 7. 放大镜（`loupe.ts`）

### 7.1 三块画布的坐标契约

| 画布 | 绘制缓冲 | 用途 |
|---|---|---|
| `glCanvas` | 设备像素，正方形 | 唯一真值来源 |
| `overlayCanvas` | **= glSize**（不是 cssSize × DPR） | 取样框；与 GL 缓冲逐像素对齐 |
| `loupeCanvas` | 面板 CSS 宽 × DPR | 最近邻放大后的画面 |

覆盖层刻意取 `glSize` 而不是 CSS 尺寸：它是"设备像素叠加层"，只有与 GL 缓冲同尺寸，取样框才落在真正被采样的那一格上。尺寸被钳进 `[256, 4096]` 时 CSS 只是把画布拉伸一点点，对齐关系不动。

### 7.2 定位与两次行序翻转

```
CSS 坐标 → 设备像素：  ox = floor(x / cssSize · glSize)      // 表盘与缓冲都是正方形，一个缩放就够
覆盖层行序（左上原点）→ GL 行序（左下原点）：  glY = glSize - (by + srcH)
```

`readBlock` 拿回的是 GL 行序：块的第 `r` 行是 GL 行 `glY + r`，对应覆盖层的行 `by + r`。放大镜要"上 = 表盘上"，所以写 `ImageData` 时用 `rowOffset - sy` 索引。`loupeHex` 的坐标读数用 GL 行序输出，与 `readPixel` 的入参一致。

### 7.3 最近邻反查表

`mapX` / `mapY` 是"放大镜像素 → 源像素"的整型表，`floor(d · src / cap)`。重建条件就是最近邻映射的全部输入：`(capW, capH, srcW, srcH)` 四元组变了才重建。`ImageData` 逐帧复用，不每帧分配。全透明时用 `any` 标志跳过 `putImageData`。

### 7.4 两层放大与网格

放大镜画面经过两次最近邻：一次是反查表把每个源像素写成整格，一次是浏览器把画布从缓冲尺寸放大到 CSS 尺寸。第二次靠 CSS 的 `image-rendering: pixelated` 保持硬边。少了它浏览器会做双线性插值，网格被涂抹，"看到设备像素"这件事就不成立了。

网格画在源像素边界上：`x = round(i · capW / srcW) + shift`，两遍，白线偏移 0.5、黑线偏移 1.5。单色发丝线在任何底色上都会有一段看不见（白线在浅底、黑线在深底），两色错半像素叠画保证任何底色上都读得出格子。这是像素级工具的通用手法。

取样格单独描一次，用的就是 `loupeHex` 读的那一格。中心读数与描边必须指同一格，这是这个工具可用性的核心。描边宽度 `max(1, round(dpr))`，覆盖层描边宽度 `max(1, round(overlayWidth / 512))`。

### 7.5 窗口与钳制

`spanPx` 是源窗口边长（设备像素），也是唯一的倍率表达：span 越小放大越多，`span = min(capW, glSize)` 时是 1:1。上界取 `min(capW, glSize)`，避免窗口比源还大、取样被拉伸。下界 `MIN_SPAN = 4`：再小就没法判断自己在看一格还是几格。默认 11。

窗口居中与贴边：`bx = clamp(ox - span/2, 0, glSize - span)`。靠近表盘边缘时窗口贴边、取样点偏离窗口中心，覆盖层的矩形把它显式画出来，读数里也带着窗口边长（`x,y·Npx`）。滚轮步长恒为 1 设备像素，因为"一格"就是这个工具的原子。

## 8. 主题与调色板（`themes/`）

### 8.1 边界

`themes/*.css` 里的配色主题取自 submodule 中的上游仓库（`vendor/openhanako/desktop/src/themes/`，README §5.1），本项目不改它们的内容、只消费；`themes/index.ts` 逐个文件显式 import `catalog.ts` 列出的 11 个主题，不 glob 整个目录。`continuous-corners.css` 不在上游公开仓库里，是本项目自己的几何支援，不是配色主题。

页面自己只定义与主题无关的 token：两族字体、三个圆角半径。圆角一律写成 `calc(<r> * var(--corner-radius-scale))`，比例定义在 `styles.css` 的 `:root`，浏览器支持 `corner-shape: squircle` 时从 1 改成 1.8408964152537137（等于 `1 + 2^(-1/4)`：圆形角点离角 0.4142r，n=4 超椭圆离角 0.2250r，两者之比）。**任何与圆角绑定的内缩量都必须跟着同一个变量走**，否则在支持 squircle 的浏览器上会错位：`.hint-row` 的 `padding-right` 与 `::before` 的占位宽度都是这么写的。

### 8.2 解析优先级

```
URL ?theme=（只在首次解析时认一次） > localStorage['aaclock:theme'] > 系统明暗（midnight / warm-paper）
```

URL 只认一次（`urlConsumed`）的理由：每次都认的话，用户在下面选了"自动"也会被 URL 顶回去。`auto` 表示跟随系统，此时监听 `matchMedia` 的 `change`，且回调里复用同一个 `MediaQueryList` 实例。无法识别的 id 一律忽略、继续往下回退。`localStorage` 读写各包一层 `try`，隐私模式与某些 `file://` 环境下会直接抛。

### 8.3 计算样式到 GL palette

顺序不能倒：先落 `documentElement.dataset.theme`，再从 `getComputedStyle` 读变量。读取只发生在应用主题的那一刻，不每帧读。

回退链（前者读不到就用后者）：

```
--text-light → --text        --text-muted → --text-light
--accent → --text            --coral → --accent        --bg-card → --bg
--border → transparent，再与 --bg 合成
```

最后一条是唯一的特例：`--border` 常写成 `rgba()`，而 GL 那边只有实色，所以先 `flatten` 到 `--bg` 上。

### 8.4 `--shadow` 的分量拆分

`--shadow` 取成 RGBA，rgb 进 `uShadow`，alpha 作为 `uShadowAlpha` 单独送。理由是可算的：浅色主题 `--shadow` 的 alpha 只有 0.04 到 0.11，一旦与底色合成，投影与背景的对比度落进一个色阶以内，屏幕上直接消失。着色器里强度是 `exp(-14d) · uShadowAlpha`：alpha 决定投影多重，衰减决定投影多宽，两者正交。

### 8.5 明暗判定

`colorScheme` 由底色的 WCAG 相对亮度反推（`relativeLuminance < 0.5` 判为暗），让原生控件与滚动条跟着走。这样省掉一张"哪些主题是暗色"的 TS 表，主题换色自动跟随。`relativeLuminance` 用的是真正的 sRGB 分段函数，不是 2.2 次幂近似。

## 9. 装配与主循环（`main.ts`）

### 9.1 帧预算

每帧固定工作：一次 `Date.now()`、三次 `wrapTau`、一次 `drawArrays`（成本 ∝ `S²·n²`）、节流写 DOM。

不用 rAF 时间戳算时间的理由有两条：它的起点是页面导航而不是 1970；它表示"帧被调度的时间"，受节流与掉帧影响。走时必须按真实时钟走，所以每帧重新取 `Date.now()`。rAF 时间戳只用来算 fps：`frameTimes` 里保留最近 500 ms 的时间戳，`fps = (count - 1) · 1000 / span`。

读数写 DOM 节流到 120 ms，且只有文本真的变了才写。等宽字体加 `tabular-nums` 保证数字位数变化不抖宽度，节流则把每帧的样式重算降下来。

### 9.2 尺寸与三块画布

```
S = clamp(round(cssSide · dpr), 256, 4096)
```

下限 256 保证小窗口下覆盖层与放大镜仍有可用分辨率（放大镜的取样框、坐标读数不会糊成一片），代价是画布被 CSS 放大后每个设备像素略大于一个屏幕像素。上限 4096 只兜 GL 缓冲的硬上限，不是性能护栏：4096 的 CSS 边长约合 5700 px 高的视口，真实屏幕碰不到；性能由 `n` 决定。

`resize()` 里三件事必须同时发生，任何一处错位都会让取样框偏移：GL 缓冲尺寸、覆盖层缓冲尺寸（必须等于 GL 的）、放大镜缓冲尺寸。

### 9.3 布局的实算

- 表盘严格居中：`.dial` 是 `aspect-ratio: 1` 的方块，放大镜绝对定位在 `left: 100%` 之外，不参与布局，所以表盘不被它推偏。
- 右侧是否放得下是实算的：`need = cssSide + 190 + 52 > innerWidth` 时加 `loupe-overlay` 把放大镜收回盘内叠放。190 = 面板 168 + 间距 22，52 = 两侧 padding 26 × 2。这三个数与 CSS 里的常量重复，改动时要同步（§11.1 第 7 条）。
- 顶栏浮层能压在表盘上方，靠的是 `FIT = 0.84` 留出的那圈余地（§2.2）；`pointer-events: none` 保证它不吃表盘的指针事件。
- 收起面板时表盘上限从 72vh 提到 86vh，且立刻重跑一次 `resize()`，不等 `ResizeObserver` 的下一帧。浮标的横坐标在收起那一刻从收起按钮量下来写进 `--handle-right`，因为面板居中、右边缘随宽度浮动，只能量不能算。

### 9.4 交互代数

**命中测试**。先把本地 CSS 坐标归一化到盘面空间：

```
px = (x - half) / half,   py = -(y - half) / half      // y 翻转让"上"为正，对上着色器约定
theta = atan2(px, py)                                  // 0 在 12 点、顺时针为正
```

每根针一个分数：`|wrapPi(theta - handAngle)| + outsidePenalty + zBias`。`outsidePenalty = 10` 是一个远超任何角差的常数，等于硬否决；`zBias` 秒 0 / 分 0.004 / 时 0.008，对应画家算法里的覆盖顺序（越在上面越小），换算成角度是 0.23° / 0.46° 的优先余量。于是"抓哪儿拨哪儿"的判据是角度最近、重叠时上面的赢，而抓远处那根针的轴线附近也不会误判。

**拖动**。每次 `pointermove` 取角度增量 `wrapPi(angle - lastAngle)`，换算成时间增量 `(delta / 2π) · CIRCLE_MS[hand]`，加回当前墙上时刻写进 `setAbsolute`。用增量而不是绝对角度的原因：指针可以绕圈、可以离开表盘（`setPointerCapture` 保证事件不断），增量对绕圈天然正确。拖动期间自动冻结走时，但 `pausedByDrag` 只在"按下时本来没暂停"的情况下为真，松手只恢复自己造成的那次暂停。

**滚轮**挂在表盘与放大镜面板两处：面板现在在表盘外，盯着放大画面时也要能调。

**键盘**：`0` 解析覆盖、`1`–`9` 每轴样本数、`B` 混合空间、`F` 覆盖场、`V` 放大镜、`G` 网格、`T` 秒针运动、`Space` 暂停、`R` 校准、`H` 收起。数字键先于 `switch` 处理（它们没有 `case` 分支）；焦点在输入控件上或带修饰键时不拦截。

### 9.5 失败兜底与 DOM 契约

`must()` 缺节点直接抛、落到 `#fatal`；`optional()` 只给两个下拉用。所有控件的可见状态由单个 `syncControls()` 从字段推导，避免出现"UI 本身就是第二份真值"。`data-analytic` / `data-linear` / `data-tick` 是分段控件的值契约，`aria-pressed` 由 `syncControls` 统一刷。

## 10. 构建管线（`vite.config.ts`）

### 10.1 四个变体与两个开关

`mode` 就是变体：默认 / `minify` / `standalone` / `standalone-minify`。`standalone` 与 `minify` 两个布尔在配置函数里各算一次，不依赖 CLI 与配置文件的优先级。两个开关只管两件事：是否内联、是否压缩，互不牵连。

四种构建都落在 `dist` 且 `emptyOutDir: true`，所以产物永远是刚构建出来的那一份，代价是后一次会抹掉前一次。`assetsInlineLimit: 0` 让 Vite 自己不内联资产；`base: './'` 让产物可以从 `file://` 或任意子路径打开。

### 10.2 插件顺序即执行顺序

```
shaderSource（pre）
minifyRawShaders            （仅压缩模式）
pruneCssOutput              （仅压缩模式）
escapeNewlines（post）
inlineStandalone（post）    （仅单文件模式）
minifyHtmlOutput（post）    （仅压缩模式）
```

三条顺序约束：

- `minifyRawShaders` 必须在模块被压缩之前跑。GLSL 进了 bundle 只是一段字符串，JS 压缩器不碰字符串内容，所以必须由这个插件在 `transform` 阶段把源码字符串本身压掉。
- `escapeNewlines` 必须在压缩之后、`inlineStandalone` 之前。它要处理的是压缩器产出的模板字面量（压缩器把含换行的字符串写成反引号），而单文件模式会把 chunk 内联进 HTML，晚一步就改不到了。
- `pruneCssOutput` 自己重发 CSS 资产并改写 HTML 里的引用，所以必须排在读 HTML 的 `minifyHtmlOutput` 之前。

### 10.3 GLSL 压缩

按 C 族词法走 `glsl-tokenizer`：丢注释与空白，其余记号原字面照抄。唯一的判断是"要不要补空格"，判据有两条：

1. 两个记号在源里是否本来就相邻：`prev.position + prev.data.length === token.position`。相邻则一个字符都不插（`<<`、`+=` 这类多字符运算符被切成两个记号时靠这条保住）。
2. 不相邻时，只在"两个字面会粘成一个新记号"的场合补一个空格：词字符接词字符，或运算符尾接运算符头（`-` 接 `-` 会变成自减，`<` 接 `<` 会变成左移）。

`preprocessor` 行（`#version`）单独一行处理，前后强制换行并把 `prev` 置空，避免与相邻记号拼上。字面量一字不改，所以压缩产物与源码在记号层面逐一对应，只是没有注释与空白。

### 10.4 换行转义

JS 压缩器会把含换行的字符串写成模板字面量，换行于是真落进产物文件，文件里多出真实换行。`escapeNewlines` 在 `generateBundle` 里把"不含反斜杠、不含 `${`、且含换行"的模板字面量替换成 `JSON.stringify` 的结果：对这类字面量，原文就是字面内容，换成普通字符串是逐字等价的。带替换的、带转义的都不碰。

扫描用一条能跨越 `${}` 的正则（`/`(?:[^`\\]|\\.)*`/g`），一次吃掉一个完整的模板字面量，避免后面配对错位。

### 10.5 PurgeCSS 的判据

内容源是 bundle 里的所有 chunk 代码加 HTML，**不含 CSS 自己**：否则 CSS 里出现的变量名会把自己放行，判据变成自证。`variables: true` 删未使用的自定义属性，`keyframes: true` 删未使用的关键帧，`safelist.variables` 补上"在 JS/HTML 里出现过但 CSS 里查不到引用"的变量名（JS 用 `getComputedStyle` 按名字读变量，那些名字在 CSS 里没有 `var()` 引用）。

裁完内容变了，必须重发资产才能让文件名里的 hash 跟着内容走：`this.getFileName(this.emitFile(...))` 拿到新名字，再把 HTML 里的旧引用整体替换掉。典型收益是 `--bg-texture` 那张挂在 `warm-paper.css` 上、44 KB 的 base64 底纹。

### 10.6 内联与 HTML 压缩

`inlineStandalone` 在 `generateBundle` 里直接从 bundle 对象取 chunk 与 asset，写进 HTML 并 `delete` 掉原条目（所以不会重复产出），同时把 chunk 代码里的 `</script>` 转义成 `<\/script>`（否则模块脚本会提前闭合标签）。不读磁盘、不引插件、不欠 `@types/node`。

`minifyHtmlOutput` 只开 `collapseWhitespace` 与 `removeComments`，不碰内联的 `script` / `style`：那些是已经压过的 JS 与 CSS。

## 11. 不变量与代价

### 11.1 贯穿性不变量

1. 几何只有一份真值来源：切换采样档位只换覆盖率算法，图元与坐标不动，钟面形状不移动。
2. 覆盖率即 alpha：任何图层都不许用分支切色，否则那片锯齿只与像素位置有关，在覆盖场里一眼可见。
3. 两把尺子不许混：`covAA` 与等距线用 `uPxDial`，超采样的子样本偏移用 `uPx`。混用会让覆盖斜坡宽出 `1/FIT ≈ 1.19` 倍。
4. 覆盖层缓冲与 GL 缓冲同尺寸，取样框才落在真正被采样的那一格上。
5. 时间只受显式操作影响：暂停恢复是赋值重构，拖动是增量累加，校准是清零。
6. 几何常量存在两处（`dial.frag` 的 `const` 与 `DIAL.ts`），改一处必须改另一处，无编译期保障。
7. 与圆角绑定的内缩量必须乘 `--corner-radius-scale`；布局常量（168 / 22 / 26）在 TS 与 CSS 两处重复，改动要同步。
8. 每帧成本只由 `S²·n²` 决定：颜色、主题、视图开关都不改变填充率，只有采样档位改变它。

### 11.2 代价清单

- 填充率是唯一的性能变量：`S² · n²` 次 `shade()`。720 px 画布、9×9 是 51.8 万像素 × 81 ≈ 4200 万次着色，每次 `shade()` 还要算约十个 SDF（含 `atan`、`sqrt`、`exp`）。实测约 42 fps；同一画布 4×4 是 140 fps、1×1 是 144 fps。4×4 与 1×1 都贴着刷新率天花板，只有 9×9 真正触到填充率饱和。
- 解析覆盖是 1 次着色/像素，成本约为 9×9 超采样的 1/81，是"免费"的那条路径。
- 覆盖场的成本恒为一次 `sdKeyUnion`（约十个 SDF），与采样档位无关。
- `readPixels` 是管线停顿，每帧最多两次，且只在放大镜开着时发生。
- 放大镜每帧的成本是 `capW · capH` 次查表加一次 `putImageData`，反查表本身有缓存，尺寸不变不重建。
